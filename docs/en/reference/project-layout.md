# Reference: project layout and scripts

Unity 6 (6000.4.11f1), Universal Render Pipeline 17.4, uGUI, the built-in
input manager. No other packages and no Asset Store content.

## Folders

| Path | Contents |
|------|----------|
| `Assets/Scenes/Main.unity` | the only scene: one object, `Bootstrap` |
| `Assets/Scripts/` | the game |
| `Assets/Editor/` | build script, graphics setup, headless runners |
| `Assets/Resources/Models` | FBX models: character, monster, railing, column, lamp, goal, scanned props |
| `Assets/Resources/Textures`, `Sky` | PBR texture sets, particle sprite, HDRI sky |
| `Assets/Resources/Materials` | generated by `GraphicsSetup`; loaded by name at run time |
| `Assets/Resources/Audio/Farts` | 63 fart recordings and their attribution |
| `Assets/Settings` | three render pipeline assets with their renderers |
| `Assets/Plugins/Android/BtLink.androidlib` | Java helper and manifest for Bluetooth play |
| `Assets/Icon.png` | app icon |
| `Tools/assets`, `Tools/blender`, `Tools/dev` | scripts that produce the assets; link test |
| `.github/workflows/build.yml` | builds the packages on GitHub ([how](../how-to/build-in-github-actions.md)) |
| `docs/` | this documentation, English and Czech |
| `Builds/`, `Logs/`, `Shots/`, `FartSounds/`, `Library/` | outputs; not in git |

## Game scripts (`Assets/Scripts`)

| Script | Role |
|--------|------|
| `GameBootstrap` | entry point: by session mode builds the menu backdrop or the world, goal, competitors, farts, monster |
| `Session` | what this run is playing (menu / solo / host / joined), kept across scene loads; reads the command line |
| `MainMenu` | title screen: solo, host, join by list or code; `MenuOrbit` moves its camera |
| `Arena` | the arena's dimensions, shared by building, collisions and navigation |
| `ArenaBuilder` | slabs, ramps, railings, columns, beams, lamps, props, markings |
| `MeshFactory` | procedural boxes with UVs in metres |
| `Mats` | material library (`Resources/Materials`) |
| `LightingRig` | HDRI sky, sun, ambient, fog, reflection probes, post-processing, the day-to-gloom mood |
| `GameManager` | roster, farts, score, winner, match time, restart |
| `Competitor` | what players and bots share: backpack, score, blasting, being knocked out |
| `PlayerController` | the person on this device: movement, view, expelling, blasting, the scare |
| `GameInput` | controls in one place: keyboard and mouse, or touch |
| `AICompetitor` | bots: collect, deliver, blast, use ramps |
| `NavPlanner` | path planning on one deck (visibility graph round obstacles) |
| `CharacterVisual` | character model, procedural run animation, gas tank |
| `FartPickup` | a collectable fart |
| `GoalZone` | the goal's trigger |
| `GasFx` | particle effects |
| `FartAudio` | fart sounds: recordings, synthesis as fallback |
| `FartMonster` | the monster's behaviour, and the gloom it brings |
| `MonsterVisual` | the monster's model and procedural animation |
| `MonsterAudio` | the monster's sounds, all synthesised |
| `Hud` | in-game HUD, touch controls' graphics, announcements, final ranking |
| `NetLink` | the connection between two devices: TCP with a UDP beacon, or Bluetooth |
| `BluetoothLink` | C# side of the Bluetooth helper (Android only) |
| `NetGame` | keeps a two-player match in step: host state out, joiner's position and requests in |
| `NetPuppet` | a competitor steered from the other device |
| `NetBot` | dev tool: plays a two-player match by itself and logs it |
| `DevCapture` | dev tool: one screenshot from a built game |
| `Spinner` | turns the goal's fan |

| Script | Role |
|--------|------|
| `BuildGame` | desktop and Android builds |
| `GraphicsSetup` | render pipelines, quality levels, texture import settings, materials |

## Conventions

- The world is built from code; the scene file stays empty. New things are
  created in `GameBootstrap`, not placed in the editor.
- Materials are loaded by name and must be created in `GraphicsSetup`, so that
  their shader variants end up in builds.
- Models are instantiated under a wrapper object; parts and material slots are
  found by name.
- Everything that changes the state of a match must also work when this device
  has only joined somebody else's match: see
  [How two-player works](../explanation/two-player-design.md).
- On-screen text is Czech. Code, comments and logs are English.
